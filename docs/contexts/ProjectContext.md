# Bounded Context: Project Management

## Назначение и границы контекста

**Project Management** — структурообразующий контекст системы. Он отвечает за управление иерархией объектов, в рамках которых ведётся учёт трудозатрат: от клиента верхнего уровня до конкретной задачи, к которой привязывается Ticket.

**Что входит в контекст:**
- Создание и ведение клиентов (Client)
- Создание и ведение проектов (Project), принадлежащих клиентам
- Создание и ведение запросов на изменение (CR), принадлежащих проектам
- Создание и ведение задач (Task), принадлежащих Project или CR
- Предоставление read-моделей для использования другими контекстами (выпадающие списки, таблицы)

**Что не входит в контекст:**
- Учёт фактически затраченного времени — это зона ответственности TimesheetContext
- Тарификация и ставки — это зона ответственности WorkCatalogContext
- Управление пользователями и правами доступа — это зона ответственности IdentityContext
- Формирование отчётов — это зона ответственности ReportingContext

**Роль в карте контекстов:** Project Management является upstream-поставщиком данных для TimesheetContext (Task — обязательная ссылка для любого Ticket) и для ReportingContext (группировка отчётов по Project/CR/Task).

## Доменные модели

### Агрегаты

#### Client (Клиент)
Организация или физическое лицо, для которого выполняются работы. Является корневым агрегатом иерархии.

| Атрибут     | Тип    | Описание                          |
|-------------|--------|-----------------------------------|
| id          | UUID   | Уникальный идентификатор клиента  |
| name        | string | Наименование клиента              |
| description | string | Дополнительное описание (опционально) |

**Инварианты:**
- Наименование клиента не может быть пустым.
- Client не может быть удалён, если к нему привязан хотя бы один активный Project.

---

#### Project (Проект)
Совокупность работ, выполняемых для Client в рамках договора. Принадлежит ровно одному Client.

| Атрибут     | Тип    | Описание                                        |
|-------------|--------|-------------------------------------------------|
| id          | UUID   | Уникальный идентификатор проекта                |
| clientId    | UUID   | Ссылка на владельца Client                      |
| name        | string | Наименование проекта                            |
| status      | enum   | Статус проекта (например: Active, Closed)       |
| description | string | Дополнительное описание (опционально)           |

**Инварианты:**
- Project всегда принадлежит одному Client.
- Project не может быть удалён, если к нему привязаны Task или CR.

---

#### CR (Change Request)
Запрос на изменение, расширяющий или корректирующий скоуп Project. Не является самостоятельным Project — всегда привязан к конкретному Project.

| Атрибут     | Тип    | Описание                                |
|-------------|--------|-----------------------------------------|
| id          | UUID   | Уникальный идентификатор CR             |
| projectId   | UUID   | Ссылка на родительский Project          |
| name        | string | Наименование CR                         |
| description | string | Описание изменения (опционально)        |

**Инварианты:**
- CR всегда принадлежит ровно одному Project.
- CR не может быть перенесён в другой Project после создания.

---

#### Task (Задача)
Единица работы внутри Project или CR, к которой привязываются Ticket. Является конечной точкой иерархии со стороны Project Management.

| Атрибут    | Тип    | Описание                                             |
|------------|--------|------------------------------------------------------|
| id         | UUID   | Уникальный идентификатор задачи                      |
| projectId  | UUID   | Ссылка на Project (если задача относится к Project)  |
| crId       | UUID   | Ссылка на CR (если задача относится к CR, опционально) |
| name       | string | Наименование задачи                                  |
| description| string | Описание задачи (опционально)                        |
| estimate   | number | Эстимейт трудозатрат в часах (опционально)           |

**Инварианты:**
- Task всегда принадлежит либо Project, либо CR — не может существовать без родителя.
- Task, к которой привязаны Ticket, не может быть удалена.

---

### Read Models

| Read Model       | Описание                                                                   |
|------------------|----------------------------------------------------------------------------|
| **Client List**  | Отфильтрованный список всех Client с базовыми атрибутами. Используется в выпадающих списках и таблицах. |
| **Project List** | Список Project в рамках конкретного Client. Может быть отфильтрован по статусу. |
| **Task List**    | Список Task с фильтрацией по Project/CR.                                   |

## Пользовательские потоки (Use Cases)

### UC-PM-01: Создать клиента
**Актор:** Admin
**Предусловия:** пользователь аутентифицирован и обладает правами Admin.
**Сценарий:**
1. Admin вводит наименование и описание Client.
2. Система проверяет уникальность наименования (опционально, по конфигурации).
3. Система создаёт Client и публикует событие `ClientCreated`.
4. Client появляется в Client List.

**Результат:** новый Client доступен для выбора при создании Project.

---

### UC-PM-02: Создать проект
**Актор:** Admin
**Предусловия:** существует хотя бы один Client.
**Сценарий:**
1. Admin выбирает Client из Client List.
2. Admin вводит наименование, статус и описание Project.
3. Система создаёт Project, привязанный к выбранному Client, и публикует событие `ProjectCreated`.
4. Project появляется в Project List данного Client.

**Результат:** новый Project доступен для создания CR и Task.

---

### UC-PM-03: Создать Change Request (CR)
**Актор:** Admin
**Предусловия:** существует хотя бы один Project.
**Сценарий:**
1. Admin выбирает Project из Project List.
2. Admin вводит наименование и описание CR.
3. Система создаёт CR, привязанный к выбранному Project, и публикует событие `CRCreated`.

**Результат:** новый CR доступен для создания Task и привязки Ticket.

---

### UC-PM-04: Создать задачу
**Актор:** Admin
**Предусловия:** существует хотя бы один Project или CR.
**Сценарий:**
1. Admin выбирает Project или CR в качестве родительского объекта.
2. Admin вводит наименование, описание и опциональный эстимейт Task.
3. Система создаёт Task, привязанную к выбранному Project или CR, и публикует событие `TaskCreated`.
4. Task появляется в Task List.

**Результат:** новая Task доступна для привязки Ticket в TimesheetContext.

---

### UC-PM-05: Просмотр списков (Client List / Project List / Task List)
**Актор:** Admin, Manager, Employee
**Сценарий:**
1. Актор открывает нужный список.
2. Система возвращает Read Model с поддержкой фильтрации:
   - Client List: без обязательных фильтров, поиск по наименованию.
   - Project List: фильтр по Client, фильтр по статусу.
   - Task List: фильтр по Project и/или CR.
3. Актор выбирает нужную запись для дальнейших действий (навигация, привязка Ticket, и т.д.).

**Результат:** актор получает актуальный список объектов с применёнными фильтрами.
