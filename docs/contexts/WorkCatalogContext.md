# Bounded Context: Work Catalog

## Назначение и границы контекста

**Work Catalog** — справочный (supporting) контекст. Его назначение — предоставлять другим контекстам неизменяемые классификаторы и тарифные справочники, необходимые для корректного учёта трудозатрат и расчёта стоимости работ.

Данные этого контекста изменяются редко (администратором) и потребляются остальными контекстами в режиме **read-only**. Контекст не содержит бизнес-логики обработки трудозатрат — он является поставщиком конфигурационных значений.

**Что входит в контекст:**
- Управление тарифными ставками (Rate)
- Управление функциональными ролями исполнителей (Role)
- Управление видами выполняемых работ (Work)
- Предоставление read-моделей для использования в других контекстах

**Что не входит в контекст:**
- Применение Rate к конкретному Ticket — это зона ответственности TimesheetContext
- Назначение Role пользователю — это зона ответственности IdentityContext
- Группировка Ticket по Work в отчётах — это зона ответственности ReportingContext
- Любые сущности, связанные с конкретными клиентами, проектами или задачами

**Роль в карте контекстов:** Work Catalog является upstream-поставщиком для TimesheetContext (Rate фиксируется на момент создания Ticket) и для ReportingContext (Work используется как измерение группировки). Отношение — Customer-Supplier: изменение справочников влияет на поведение downstream-контекстов, поэтому версионирование и обратная совместимость критичны.

## Доменные модели

### Агрегаты

#### Rate (Ставка)
Тарифная ставка в единицу времени, применяемая к Role или Work при расчёте стоимости Ticket.

| Атрибут       | Тип      | Описание                                          |
|---------------|----------|---------------------------------------------------|
| id            | UUID     | Уникальный идентификатор ставки                   |
| amount        | decimal  | Сумма ставки                                      |
| currency      | string   | Валюта (например: USD, EUR, RUB)                  |
| effectiveFrom | date     | Дата вступления ставки в силу                     |
| roleId        | UUID     | Ссылка на Role, к которой применяется ставка (опционально) |
| workId        | UUID     | Ссылка на Work, к которой применяется ставка (опционально) |

**Инварианты:**
- Amount должен быть положительным числом.
- EffectiveFrom не может быть изменён после того, как ставка была применена к хотя бы одному Ticket.
- Rate применяется к Ticket на момент его создания и не изменяется ретроспективно.

---

#### Role (Роль)
Функциональная роль исполнителя, определяющая его специализацию (например: Developer, QA, PM). Влияет на Rate при расчёте стоимости работ.

| Атрибут     | Тип    | Описание                                         |
|-------------|--------|--------------------------------------------------|
| id          | UUID   | Уникальный идентификатор роли                    |
| name        | string | Наименование роли (например: Developer, QA, PM)  |
| description | string | Описание роли (опционально)                      |

**Инварианты:**
- Наименование Role должно быть уникальным.
- Role не может быть удалена, если к ней привязаны Rate или пользователи в IdentityContext.

---

#### Work (Работа)
Классификатор вида выполняемой деятельности (например: Development, Consulting, Testing). Используется для группировки Ticket в отчётах и для тарификации.

| Атрибут     | Тип    | Описание                                                  |
|-------------|--------|-----------------------------------------------------------|
| id          | UUID   | Уникальный идентификатор вида работ                       |
| name        | string | Наименование вида работ (например: Development, Consulting) |
| description | string | Описание вида работ (опционально)                         |

**Инварианты:**
- Наименование Work должно быть уникальным.
- Work не может быть удалена, если она используется в существующих Ticket.

---

### Read Models

| Read Model    | Описание                                                                                 |
|---------------|------------------------------------------------------------------------------------------|
| **Work List** | Полный список доступных Work. Используется в TimesheetContext при добавлении Ticket и в ReportingContext при группировке. Доступен всем ролям (Admin, Manager, Employee). |
| **Role List** | Список функциональных Role. Используется в IdentityContext при назначении Role пользователю и в WorkCatalogContext при привязке Rate. Доступен Admin. |
| **Rate List** | Список ставок Rate с возможностью фильтрации по roleId и workId. Доступен Admin. |

## Пользовательские потоки (Use Cases)

### UC-WC-01: Создать ставку (Rate)
**Актор:** Admin
**Предусловия:** пользователь аутентифицирован и обладает правами Admin. Существует хотя бы одна Role или Work, к которой привязывается ставка.
**Сценарий:**
1. Admin указывает сумму, валюту и дату вступления в силу.
2. Admin опционально выбирает Role и/или Work, к которым применяется ставка.
3. Система проверяет корректность данных (сумма > 0, дата заполнена).
4. Система создаёт Rate и публикует событие `RateCreated`.

**Результат:** новая Rate доступна для применения к Ticket в TimesheetContext.

---

### UC-WC-02: Создать роль (Role)
**Актор:** Admin
**Предусловия:** пользователь аутентифицирован и обладает правами Admin.
**Сценарий:**
1. Admin вводит наименование и описание Role.
2. Система проверяет уникальность наименования.
3. Система создаёт Role и публикует событие `RoleCreated`.

**Результат:** новая Role доступна для назначения пользователям в IdentityContext и для привязки Rate.

---

### UC-WC-03: Создать вид работ (Work)
**Актор:** Admin
**Предусловия:** пользователь аутентифицирован и обладает правами Admin.
**Сценарий:**
1. Admin вводит наименование и описание Work.
2. Система проверяет уникальность наименования.
3. Система создаёт Work и публикует событие `WorkCreated`.

**Результат:** новый Work доступен в Work List и может быть указан при добавлении Ticket.

---

### UC-WC-04: Просмотр Work List
**Актор:** Admin, Employee, Manager
**Сценарий:**
1. Актор запрашивает список доступных Work (например, при заполнении формы добавления Ticket).
2. Система возвращает полный Work List.
3. Актор выбирает нужный Work.

**Результат:** актор получает актуальный список видов работ для выбора.
