# Bounded Context: Reporting

## Назначение и границы контекста

**Reporting** — аналитический (supporting) контекст, отвечающий за формирование агрегированных представлений данных о трудозатратах и их экспорт во внешние форматы. Является конечным потребителем данных из TimesheetContext и предоставляет результаты руководителям и администраторам.

**Что входит в контекст:**
- Формирование сводных отчётов (Report) на основе Ticket по заданным параметрам
- Хранение сформированных отчётов
- Экспорт отчётов в файлы (CSV, XLSX, PDF) — Report Export
- Предоставление read-моделей для просмотра списка отчётов и выгрузок

**Что не входит в контекст:**
- Хранение первичных данных (Ticket) — это зона ответственности TimesheetContext
- Управление пользователями и группами — это зона ответственности IdentityContext
- Управление справочниками (Work, Role) — это зона ответственности WorkCatalogContext
- Создание структурных объектов (Task, Project) — это зона ответственности ProjectContext

**Роль в карте контекстов:** Reporting является downstream-потребителем всех остальных контекстов. Данные для построения отчётов приходят из TimesheetContext (Ticket), ProjectContext (Project, CR, Task), IdentityContext (Employee, Group) и WorkCatalogContext (Work). Отношение — Conformist или Anti-Corruption Layer в зависимости от степени связанности с моделями upstream-контекстов.

**Важное архитектурное решение:** Report Export — это артефакт (Value Object), а не агрегат. Файл выгрузки не является самостоятельной сущностью с идентификатором жизненного цикла — он производится из Report по запросу и может быть воспроизведён повторно.

## Доменные модели

### Агрегаты

#### Report (Отчёт)
Агрегированное представление Ticket за заданный период и набор параметров фильтрации/группировки. Сохраняется для последующего просмотра и экспорта.

| Атрибут       | Тип      | Описание                                                                     |
|---------------|----------|------------------------------------------------------------------------------|
| id            | UUID     | Уникальный идентификатор отчёта                                              |
| name          | string   | Наименование отчёта                                                          |
| createdBy     | UUID     | Ссылка на User, создавшего отчёт                                             |
| createdAt     | datetime | Дата и время формирования отчёта                                             |
| periodFrom    | date     | Начало периода выборки                                                       |
| periodTo      | date     | Конец периода выборки                                                        |
| filters       | JSON     | Набор применённых фильтров (по Employee, Group, Project, CR, Task, Work)     |
| groupBy       | string[] | Измерения группировки (Employee, Project, CR, Work, Task)                    |
| data          | JSON     | Агрегированные данные отчёта (snapshot на момент формирования)               |

**Инварианты:**
- PeriodFrom не может быть позже periodTo.
- Данные отчёта (data) фиксируются на момент формирования и не обновляются автоматически при изменении Ticket — это намеренный snapshot.
- Report не может быть изменён после создания; для получения актуальных данных создаётся новый Report.

---

### Value Objects

#### Report Export (Выгрузка отчёта)
Файл, сформированный из одного или нескольких Report. Является результирующим артефактом операции экспорта — не агрегатом с собственным жизненным циклом.

| Атрибут    | Тип      | Описание                                              |
|------------|----------|-------------------------------------------------------|
| reportIds  | UUID[]   | Список идентификаторов Report, включённых в выгрузку  |
| format     | enum     | Формат файла: CSV, XLSX, PDF                          |
| generatedAt| datetime | Дата и время генерации файла                          |
| fileRef    | string   | Ссылка или путь к сгенерированному файлу              |

---

### Read Models

| Read Model                  | Описание                                                                                              |
|-----------------------------|-------------------------------------------------------------------------------------------------------|
| **Report List**             | Список сохранённых Report с мета-информацией (наименование, период, автор, дата создания).            |
| **Exported Reports List**   | Список доступных файлов выгрузок с указанием формата и даты генерации.                                |

## Пользовательские потоки (Use Cases)

### UC-RP-01: Сформировать отчёт (Add Report)
**Актор:** Manager, Admin
**Предусловия:** пользователь аутентифицирован. В TimesheetContext существуют Ticket за запрашиваемый период.
**Сценарий:**
1. Актор задаёт параметры отчёта:
   - Период (дата от/до).
   - Фильтры: Employee, Group, Project, CR, Task, Work (опционально).
   - Измерения группировки (например: по Employee и Work).
   - Наименование отчёта.
2. Система запрашивает данные Ticket из TimesheetContext с учётом фильтров.
3. Система агрегирует данные по заданным измерениям.
4. Система сохраняет Report (snapshot) и публикует событие `ReportAdded`.
5. Report появляется в Report List.

**Результат:** сформирован и сохранён Report с агрегированными данными о трудозатратах за указанный период.

---

### UC-RP-02: Просмотр Report List
**Актор:** Manager, Admin
**Сценарий:**
1. Актор открывает Report List.
2. Актор опционально фильтрует список по автору, периоду, наименованию.
3. Система возвращает список сохранённых Report с мета-информацией.
4. Актор выбирает Report для просмотра деталей или инициации экспорта.

**Результат:** актор видит актуальный список ранее сформированных отчётов.

---

### UC-RP-03: Выгрузить отчёты (Export Reports)
**Актор:** Manager, Admin
**Предусловия:** существует хотя бы один Report в Report List.
**Сценарий:**
1. Актор выбирает один или несколько Report из Report List.
2. Актор указывает формат выгрузки (CSV, XLSX, PDF).
3. Система генерирует файл Report Export из данных выбранных Report.
4. Система публикует событие `ReportsExported`.
5. Ссылка на файл добавляется в Exported Reports List.
6. Актор скачивает файл.

**Результат:** данные отчётов экспортированы в файл выбранного формата.

---

### UC-RP-04: Просмотр Exported Reports List
**Актор:** Manager, Admin
**Сценарий:**
1. Актор открывает список выгрузок.
2. Система возвращает Exported Reports List с указанием формата, даты генерации и ссылки на файл.
3. Актор скачивает нужный файл повторно (если ссылка ещё действительна).

**Результат:** актор получает доступ к ранее сгенерированным файлам выгрузок.
